## 墓园段的随机流约定（改这一段前先读）

`park_env.py` 全文共用一条 `random` 序列，`on_path()` / `pump_plan` / `tree_extras` 决定其后的散布（南瓜伴生、草丛、地斑、树）哪些候选被舍弃。**改这些规则或墓园段对全局 `random` 的消耗，全园散布都会重新随机**（树、草丛、长椅变体、远山全部换位）。墓园段的约定：

- 段内新增的随机一律走墓园自己的 `rgv`；彼岸花走 `rlg`；全局 `random` 只保留改造前就有的消耗（枯树 + 段末 `GV_LEGACY_DRAWS` 占位）。
- 新占到的地面不进 `on_path()`：原地上已有的草丛 / 地斑在段末按位置确定性清掉；固定件要挪（如打卡南瓜）就在建完后整体平移，再改碰撞圆与 POI 记录。
- 树若落进新址，在树段里确定性推出（`GV_TREE_PUSH`），不重新抽随机数。
- 挪固定件（长椅、稻草人、灯杆、蘑菇圈……）之前先 grep 它的坐标有没有进 `tree_extras` / `on_path` 的避让表：进了就只能让避让表继续按原位算（长椅见 `GV_BENCH_TREE_XY`），否则全园的树重新随机。
- 重跑后除了逐网格字节比对，再做一遍顶点级比对（墓园评审目录 `shots/graveyard_review/b3/glb_vertex_diff.py <旧.glb> <新.glb>`）：按材质合并的网格里，数量比对看不出「新件落在错位置」。
- 重跑园区后，拿改动前后的 glb 逐网格比对：除了预期变化的网格，其余应当字节相同。

## 坐标换算（重要）

Blender (x, y, z) → glTF (x, z, -y)。colliders.json 已自动换算到 app 空间；在 Blender 里新加道具时记得同步加 `collider(x, y, r)`。
